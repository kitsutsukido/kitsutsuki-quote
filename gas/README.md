# 見積もりアプリ用 Apps Script(GAS)連携コード

`Code.gs` は、このアプリ(謎文具キツツキ堂見積台帳)専用のGoogleスプレッドシート連携スクリプトです。バージョン管理のためにリポジトリへ保存しているだけで、Apps Script本体への反映は手作業で行います。

在庫管理アプリ(謎文具キツツキ堂在庫台帳)用のApps Scriptプロジェクト・デプロイとは完全に別物です。このコードを貼り付ける際、在庫アプリ側の既存コードやデプロイには一切触れません。

## 扱うシート

| シート名 | 内容 |
|---|---|
| 商品案件 | `projects`(商品ごとの印刷ロット) |
| 見積もりセッション | `sessions`(仮見積もり・確定見積もり) |
| 見積もり明細 | `lineItems`(見積もりの明細行。`processes`はJSON文字列として保存) |
| 梱包グループマスタ | `groups`(梱包グループの階層構造) |
| 収支設定 | `profitSettings`(案件ごとの販売価格・分配率。アプリ内は`projectId`キーのオブジェクトだが、シート上は1行1案件の表として保存) |
| 販売パターン | `profitPatterns`(案件ごとの委託販売・ショップ販売パターン) |

商品マスタ・資材マスタ(在庫アプリが管理)はこのスクリプトでは一切読み書きしません。

## 貼り付け・デプロイ手順

1. 在庫アプリと連携している(商品マスタ・資材マスタがある)Googleスプレッドシートを開く
2. メニューの「拡張機能」→「Apps Script」を開く
3. 左側のファイル一覧で「+」→「スクリプト」を選び、新しいスクリプトファイルを追加する(ファイル名は自由。例:`QuoteSync.gs`)
   - **既存の`Code.gs`(在庫アプリ用)は絶対に上書き・削除しないこと**
4. 新しく追加したファイルの中身を全部消し、このリポジトリの`gas/Code.gs`の内容を貼り付けて保存する
5. 上部の「デプロイ」→「新しいデプロイ」を選択
6. 「種類の選択」(歯車アイコン)で「ウェブアプリ」を選ぶ
7. 「次のユーザーとして実行」は「自分」、「アクセスできるユーザー」は「全員」に設定して「デプロイ」を押す
   - これは在庫アプリのデプロイとは別枠の、新規のウェブアプリデプロイになります
8. 初回はGoogleアカウントの承認画面が出るので許可する
9. 発行された「ウェブアプリのURL」を見積もりアプリ側の設定(今後実装予定の同期設定画面、または一時的に環境変数など)に控えておく

## 動作確認

- `doGet`(ブラウザでURLを直接開く、または`curl`)で `{"status":"ok","data":{...}}` が返ってくることを確認する
- `doPost`は `Content-Type: text/plain;charset=utf-8` で以下のようなJSONボディを送る想定です(在庫アプリの`push`関数と同じ`mode: "no-cors"`のfetchパターンを使う場合、レスポンス本文は読めません):

```json
{
  "type": "full-sync",
  "data": {
    "projects": [...],
    "sessions": [...],
    "lineItems": [...],
    "groups": [...],
    "profitSettings": { "prj-shinkai": { "price": 1800, "facilityRate": 0, "localSalesRate": 0, "royaltyRate": 0, "taxRate": 10 } },
    "profitPatterns": [...]
  }
}
```

送信するフィールドは全部そろえる必要はなく、`data`に含まれるキーだけが上書きされます(在庫アプリの`full-sync`と同じ挙動)。

## 今回のスコープ外

- アプリ本体(React側)からこのURLへ実際にpush/pullするコードの実装は、今回は含んでいません(GASコードの新規作成のみが依頼内容のため)。組み込みが必要になったら別途対応します。
- 在庫アプリにある「複数スプレッドシートへの分割送信」「Gmail自動取込」「委託先スプレッドシート自動巡回」などの仕組みは、見積もりアプリでは不要なため実装していません。
