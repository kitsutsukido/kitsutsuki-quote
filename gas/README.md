# 見積もりアプリ用 Apps Script(GAS)連携コード

`Code.gs` は、このアプリ(謎文具キツツキ堂見積台帳)専用のGoogleスプレッドシート連携スクリプトです。バージョン管理のためにリポジトリへ保存しているだけで、Apps Script本体への反映は手作業で行います。

在庫管理アプリ(謎文具キツツキ堂在庫台帳)用のApps Scriptプロジェクト・デプロイとは完全に別物です。このコードを貼り付ける際、在庫アプリ側の既存コードやデプロイには一切触れません。

**運用方針：シリーズ(ジャンル)ごとに別スプレッドシート。** 招待状シリーズ・魔法の仕立て屋シリーズのように、商品のシリーズ単位でスプレッドシートを分けて管理します。`Code.gs`自体はどのシリーズでも同じ内容を使い回せるので、下記の「貼り付け・デプロイ手順」を**シリーズごとに1回ずつ繰り返して**ください。1つのスプレッドシート・1つのデプロイ・1つのウェブアプリURLが、1つのシリーズに対応します。発行された各ウェブアプリURLは、見積もりアプリ側の「設定・連携」画面で、対応するシリーズの欄にそれぞれ登録します。

## 扱うシート

| シート名 | 内容 |
|---|---|
| 商品案件 | `projects`(商品ごとの印刷ロット) |
| 見積もりセッション | `sessions`(仮見積もり・確定見積もり) |
| 見積もり明細 | `lineItems`(見積もりの明細行。`processes`はJSON文字列として保存) |
| 梱包グループマスタ | `groups`(梱包グループの階層構造) |
| 収支設定 | `profitSettings`(案件ごとの販売価格・分配率。アプリ内は`projectId`キーのオブジェクトだが、シート上は1行1案件の表として保存) |
| 販売パターン | `profitPatterns`(案件ごとの委託販売・ショップ販売パターン) |

商品マスタ・資材マスタ(在庫アプリが管理)はこのスクリプトでは一切読み書きしません。

## 貼り付け・デプロイ手順(シリーズごとに1回ずつ繰り返してください)

対象のシリーズ(例:招待状シリーズ)に対応する、在庫アプリと連携しているGoogleスプレッドシートごとに、以下を実施します。

1. そのシリーズの、在庫アプリと連携している(商品マスタ・資材マスタがある)Googleスプレッドシートを開く
2. メニューの「拡張機能」→「Apps Script」を開く
3. 左側のファイル一覧で「+」→「スクリプト」を選び、新しいスクリプトファイルを追加する(ファイル名は自由。例:`QuoteSync.gs`)
   - **既存の`Code.gs`(在庫アプリ用)は絶対に上書き・削除しないこと**
4. 新しく追加したファイルの中身を全部消し、このリポジトリの`gas/Code.gs`の内容を貼り付ける。先頭付近の `const SHARED_SECRET = "";` の `""` の中に、推測されにくい合言葉(例:ランダムな英数字20文字以上)を入れて保存する
   - 合言葉はシリーズごとに別の文字列にしてよい。チャットやGitHubには貼らないこと
5. 上部の「デプロイ」→「新しいデプロイ」を選択
6. 「種類の選択」(歯車アイコン)で「ウェブアプリ」を選ぶ
7. 「次のユーザーとして実行」は「自分」、「アクセスできるユーザー」は「全員」に設定して「デプロイ」を押す
   - これは在庫アプリのデプロイとは別枠の、新規のウェブアプリデプロイになります
8. 初回はGoogleアカウントの承認画面が出るので許可する
9. 発行された「ウェブアプリのURL」と、手順4で決めた合言葉を、見積もりアプリの「設定・連携」画面にある、このシリーズに対応するURL欄・合言葉欄に貼り付ける
   - `SHARED_SECRET` を後から変えた場合は、「デプロイを管理」→編集→新バージョンで再デプロイが必要

**他のシリーズが残っている場合は、そのシリーズのスプレッドシートに対して1から手順を繰り返してください。** シリーズの数だけ、スプレッドシート・デプロイ・ウェブアプリURLがそれぞれ別々に存在することになります。

## 合言葉(共有シークレット)による認証

ウェブアプリは「アクセスできるユーザー：全員」で公開するため、URLを知っている人は誰でもアクセスできてしまいます。そこで `SHARED_SECRET` と一致する合言葉を持たないリクエストを拒否します。

- `doGet`: URLの `?secret=合言葉` を確認
- `doPost`: JSONボディの `secret` フィールドを確認
- 不一致の場合は `{"status":"error","message":"unauthorized"}` を返し、シートには一切触れません
- `SHARED_SECRET` が空文字の場合は確認を行いません(非推奨。必ず設定してください)

## 動作確認

- `doGet`(`URL?secret=合言葉` をブラウザで開く、または`curl`)で `{"status":"ok","data":{...}}` が返ってくることを確認する。合言葉なし・誤りの場合は `unauthorized` になること
- `doPost`は `Content-Type: text/plain;charset=utf-8` で以下のようなJSONボディを送る想定です(在庫アプリの`push`関数と同じ`mode: "no-cors"`のfetchパターンを使う場合、レスポンス本文は読めません):

```json
{
  "type": "full-sync",
  "secret": "合言葉",
  "data": {
    "projects": [...],
    "sessions": [...],
    "lineItems": [...],
    "groups": [...],
    "profitSettings": { "prj-shinkai": { "price": 1800, "facilityRate": 0, "localSalesRate": 0, "royaltyRate": 0, "taxRate": 10 } },
    "profitPatterns": [...]
  }
}
```

送信するフィールドは全部そろえる必要はなく、`data`に含まれるキーだけが上書きされます(在庫アプリの`full-sync`と同じ挙動)。

## 今回のスコープ外

- アプリ本体(React側)からこのURLへ実際にpush/pullするコードの実装は、今回は含んでいません。見積もりアプリの「設定・連携」画面はシリーズごとのURL入力欄までを用意済みで、実際のfetch処理の組み込みは別途対応します(その際、GETは`?secret=`、POSTはボディの`secret`に設定画面の合言葉を付けます)。
- 在庫アプリにある「Gmail自動取込」「委託先スプレッドシート自動巡回」などの仕組みは、見積もりアプリでは不要なため実装していません。
